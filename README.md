### 为什么需要「给 AI 的摘要」这几个文件

主页面是体积很大的自包含 HTML，**AI 抓取器读不到里面的数值**：读数全都以内联 JS 变量和 canvas 图形的形式存在，
静态抓取即便能命中这些数字，拿到的也只是没有口径与上下文的裸代码，读不出「哪个指标、当前是多少、该怎么判读」。

三个原因：

1. **数值全在 JS 变量里**——所有读数存在 `window.DATA` 这个大对象里，不执行 JavaScript 的抓取器只能看到 `{ratio:…,…}` 这样的裸代码；
2. **图是 canvas 画的**——ECharts 把曲线画进位图，DOM 里没有任何 `<text>`，就算执行了 JS 也抓不到文字；
3. **体积超限**——整页体积远超多数 AI 网页抓取工具的正文阈值。

所以每日构建会额外产出三份纯文本：

| 文件 | 大小 | 内容 |
|---|---|---|
| `llms.txt` | 很小的纯文本 | 20 个指标的当前读数 + 各自数据截止日 + 判读口径 + 交叉判读提示 + 名词速查 |
| `snapshot.md` | 很小的纯文本 | 同上内容的 Markdown 版（在 GitHub 上可直接渲染阅读） |
| `latest.json` | 很小的结构化文本 | 同上内容的结构化版本，与 `data.json` 同源同口径的精简版 |

**用法**：把 `llms.txt` 的地址发给大模型（或直接把全文贴进对话框），它就能真的回答「现在 A 股什么位置」，而不只是复述指标定义。

## 和上游原版（wwww1998）比，改了些什么

本仓库复制自 [wwww1998/earl-etf-dashboard](https://github.com/wwww1998/earl-etf-dashboard)（原版在线看板：<https://wwww1998.github.io/earl-etf-dashboard/>）。
**20 个指标的算法、图表口径完全没动**，改的全部是「怎么让它跑得下去」。

一句话概括上游的做法：**关掉云端，改在本机跑**。原作者 2026-09-18 把 `schedule` 注释掉，改用 Windows 计划任务每天 18:30 在自己电脑上执行、跑完再 `git push`。在他自己机器上没问题（家里宽带 IP 不会被中证官网当爬虫封、本地有完整的原始缓存），但换台机器就复现不了。

本版改成**纯云端**，不依赖任何本机环境。

| 项目 | 上游原版 | 本版 |
|---|---|---|
| 谁在跑 | 本机 Windows 计划任务，云端 `schedule` 已注释 | GitHub 云端，每天 18:30 |
| 仓库体积 | 大（长年全量累积） | **明显更小** |
| 每天提交量 | 较大 | 较小 |
| 一次运行耗时 | 本机跑，无上限 | **数分钟（云端）** |
| 中证 403 熔断 | 阈值 2，**单只**指数连撞两次就全局熔断 | 阈值 3，且**只数不同代码** |
| 抓取顺序 | 写死在代码的字典里 | **最落后的先抓** |
| M13 交易集中度 | 依赖 `cache/tc_raw/`（只有本机有）→ 云端恒空、序列永久冻结 | 从 `tc_recent.csv.gz` 借 5200+ 只股票池 |
| `actions/cache` | 固定 key，永不更新，还会盖掉 checkout 的新文件 | 已删除 |
| `requirements.txt` | 3 个包，缺 `akshare` | 已补齐 |
| 给 AI 的文本摘要 | 无 | `llms.txt` / `snapshot.md` / `latest.json` |

### 几个改动的原因

- **熔断阈值**：上游是「一个代码被限流，后面排队的一起被掐死」。实测 `931591` 连撞 3 次 403 就触发全局熔断，导致排在它后面的 M6B、M9 **停更 9 个交易日**——而源头数据一直有。本版把「单只被限流」和「整个 IP 被封」分成两类信号处理。
- **仓库体积**：上游每天全量重写 `tc_recent.csv`（明文）+ `data.js`（冗余副本），长年累积把仓库越滚越大。本版把前者压成 `.csv.gz`（体积大幅缩小），后者直接不入库（它就是 `data.json` 的副本，构建时缺失会现生成）。
- **提速明显**：其中一大截只来自一件事——中债登接口超时设的是 60 秒 × 3 次，整段其实全花在等超时上，收紧到 18 秒 × 2 次即可。剩下的时间基本砍不掉：还有一段是抓指数时**被迫的间隔等待**（间距一压，中证官网就封 IP，反而更慢）。

### 两个版本怎么选

- **不想管、要长期稳定** → 本版（纯云端，数分钟跑完，仓库轻量）
- **本机能常开、要最快** → 上游（本机跑不受 403 限制，代码更简单）
- **都留着** → 上游当主站、本版当备选，任一方挂了另一个还在

# 第一部分 · 先搞懂五个基础概念

这一节比后面的指标列表更重要。看不懂指标，通常是这几个概念没通。

## 1. 分位（百分位）—— 看板里最重要的读数

**分位 = 当前值在历史样本里的排名位置。**

- 「85.4% 分位」的意思是：**历史上只有 14.6% 的时间，这个指标比现在更高。**
- 「20% 分位」的意思是：历史上 80% 的时间都比现在高，现在处在很低的位置。

分位的好处是把不同量纲的指标拉到同一把尺子上。绝对数值往往没有可比性（比如市盈率 12 倍是高还是低，得看历史上它一般在什么区间），而分位直接告诉你「在历史里算贵还是便宜」。

> ⚠️ **分位的陷阱**：它依赖样本区间。样本只有 3 年和样本有 20 年，同一个数值的分位可能差很多。所以本页每张图都标注了自己的历史起点，看的时候留意一下。

## 2. 价格指数 vs 全收益指数 —— 差别是一年约 2%

- **价格指数**：只跟踪股价涨跌，**把分红扔掉了**。上证指数、沪深300 都是价格指数。
- **全收益指数**：把分红也再投进去，所以长期走势比价格指数高，**大约每年高 2%**（A 股股息率水平）。

所以同一个「沪深300」，价格指数和全收益指数拉长十年看，能差出一大截。做长期比较时**必须用全收益指数**，否则会系统性低估。

看板里 `H00300`（沪深300全收益）、`H00922`（中证红利全收益）就是官方全收益指数。凡是标注「价格指数」的图，都会说明「收益与偏离度系统性偏低约 2%/年」。

## 3. 归一化（rebase 到 1000）—— 为什么两条线能放一起比

把两条曲线都从某个起点重新标定为 1000，之后按涨幅同比缩放。这样两条不同点位（比如 4000 点和 1200 点）的指数就能放在同一张图上比较「谁涨得多」。

看板里常见的起点：`2004-12-31 = 1000`、`2007-12-31 = 1000`。**起点选在哪里会显著影响结论**，这点在看 M5 时要特别注意。

## 4. 40 日收益差 —— 衡量「短期相对涨速」

是指标 A 减去指标 B 在最近 40 个交易日的涨跌幅之差，单位是百分点。

- 正值越大 → A 短期跑赢 B
- 负值越大 → B 短期跑赢 A

40 个交易日约两个月，这个窗口能过滤日内噪音，捕捉短期的相对强弱变化。

**关键：它是「涨速」，不是「水位」，性质是反转（均值回归）。** 涨速在数学上不可能长期维持，冲到极端必然回归。实算（M6a/M6b/M6c/M7 + M9 红利，按每次事件独立计段）：

- 进**极冷区**（近 5 年滚动分位 ≤10%）后 20–40 日，**78%–96% 回升**
- 进**过热区**（分位 ≥90%）后 20–40 日，**68%–93% 继续回落**

所以正确读法是看**滚动分位是否进极值区**（过冷＝短期跌过头，易反弹；过热＝短期涨过头，别追），而**不是**"差值的均线是否穿越零轴"。后者是趋势读法，与本指标的性质相反，本页早期版本用错过，现已统一。（详见第六部分 M6/M9 两节）

## 5. 「三项指标一起看」原则

单个指标几乎一定会骗人。估值低的时候往往还能更低，情绪热的时候往往还能更热。看板的正确用法是：

> **估值 + 情绪 + 资金，三条线同向时才下结论。**

比如：「估值分位只 20%（便宜）」+「偏股基金 3 年滚动年化 −5%（情绪冰点）」+「两融担保比例贴近 227%（杠杆已出清）」——三个方向都指向底部，这个结论就比单看一个 PE 靠谱得多。

# 第二部分 · 名词速查

| 名词 | 含义 |
|---|---|
| **PE (TTM)** | 市盈率 = 股价 ÷ 最近 12 个月每股盈利。越低越便宜 |
| **PB** | 市净率 = 股价 ÷ 每股净资产 |
| **ROE** | 净资产收益率 = 净利润 ÷ 净资产，衡量赚钱效率 |
| **盈利收益率** | = 1 ÷ PE。市盈率的倒数，可以直接和债券利率比大小 |
| **股息率** | 每股分红 ÷ 股价。红利策略的核心指标 |
| **风险溢价** | 股息率 − 10 年期国债收益率。股票相对债券多给的补偿 |
| **市赚率 (PR)** | = PE ÷ (ROE×100)。本质是「用多少倍 PE 买到 1% 的 ROE」，PR < 1 通常视为低估 |
| **滚动年化** | 把过去 N 年的累计收益换算成每年的复合收益率 |
| **布林带** | 均线上下各加 2 个标准差形成的通道。突破上轨＝过热，跌破下轨＝超跌 |
| **Z 值** | 当前值偏离均值多少个标准差。+2 以上偏高，−2 以下偏低 |
| **两融担保比例** | 融资融券账户的（现金+证券市值）÷ 负债。低于 227% 会触发强制平仓 |
| **基期归一** | 把曲线从某天重新定为 1000，之后按涨幅缩放，方便两条不同点位的线对比 |
| **滞后期 / 数据截止** | 每个数据源的发布节奏不同，图上标的是该指标自己最后一根数据的日期 |

# 第四部分 · 逐个指标详解

## 主线一：估值与性价比（判断"贵不贵"）

### M1 · 五年之锚（中证全指 000985 偏离率）

**是什么**：用**中证全指(000985)**（万得全A 的等价代理，同为全市场宽基综合指数、走势高度一致）相对它自己**五年移动平均线**偏离了多少。这是张翼轸最出名的指标之一，用来判断 A 股整体处在周期的什么位置。

**算法**：`偏离率 = (当前点位 ÷ 五年均线 − 1) × 100%`，再算这个偏离率在历史上的分位。

**页面上看到的**：五年均线、当前偏离率（%）、偏离率的历史分位、以及一条 10 年分位曲线。

**怎么读**：

| 读数 | 含义 | 通常对应 |
|---|---|---|
| 偏离率 > +10% | 高于五年均线 | 偏高，暂停定投、考虑分批减仓 |
| 偏离率 −5% ~ +10%，分位 40–60% | 均值附近 | 震荡市，无明确方向 |
| 偏离率 < −5% | 低于五年均线 | 低位区间，可加大买入 |
| 偏离率 < −20% | 显著低于五年均线 | 极端底部区域 |

**阈值（重要）**：`+10% / −5%` 是**给中证全指这一条序列单独定的**，不是通用刻度。换指数会让偏离度的**水平值整体挪位**（中证全指比万得全A 低约 5pt 量级），所以任何其他口径的门槛都不能直接搬过来；反过来，也别用本页的读数去套别人的历史文章。**本页内部（M1 / M1b / `anchor_v2.html`）用的是同一套中证全指偏离度**，口径一致。

**注意**：用的是**价格指数**（中证全指全收益版没有公开源），所以偏离度会比全收益口径系统性偏低约 2%/年。看趋势和相对高低不受影响，但别拿绝对值跟别人的全收益口径比。

---

### M1b · 五年之锚（原文口径）

**是什么**：M1 的原始版本。原文的核心判断是「**跌破五年均线下浮 20%，就是可以抄底的位置**」。

**怎么读**：页面会统计历史上这个条件被触发的次数（图上显示为「⬆x 次 / ⬇y 次」）。看的是**触发频率**，不是当前值本身——如果历史上平均两三年才触发一次，而现在正在触发，那就是很强的信号。图上的穿越箭头阈值与中证全指口径配套：**⬆ 红箭头＝偏离 ≤ −20%**（正好是跌破 MA×0.8 的位置），**⬇ 绿箭头＝偏离 ≥ +25%**，同方向 60 个交易日只标一次。

**和 M1 的区别**：M1 是「连续的分位曲线」，M1b 是「离散的触发计数」。M1 告诉你「现在多便宜」，M1b 告诉你「历史上这种便宜到什么程度出现过几次」。

---

### M2 · 股债性价比

**是什么**：把**股票的盈利回报**和**债券的利息回报**放在一起比。也叫 FED 模型 / 格雷厄姆指数。

**算法**：
```
盈利收益率 = 1 ÷ 沪深300市盈率
股债性价比 = 盈利收益率 − 10年期国债收益率
```
直觉理解：沪深300 现在的盈利回报率如果是 7%，而国债只有 1.65%，那买股票的「基础回报」比买国债高出 5.35 个百分点——这个差值越大，股票越划算。

**页面上看到的**：市盈率、市赚率（PR）、股债性价比曲线。

**怎么读**：

- **差值越高 → 股票相对债券越便宜 → 该多配股票**
- **差值越低（甚至为负）→ 股票相对债券太贵 → 该多配债券**
- 看历史分位：> 80% 分位说明股票性价比处于历史高位

**注意**：
1. 这个指标是**月频**（因为免费的指数 PE 只有月频），不是每天都能看到新点。
2. 市赚率 `PR = PE ÷ (ROE×100)`，本页的 ROE 是 `PB ÷ PE` 反推的近似值，不是财报直接披露的。PR < 1 一般视为低估。

---

### M12 · 沪深300 估值一图看全

**是什么**：把沪深300 的**走势、市盈率、市赚率**三张图上下排列，一次看全估值三要素。

**为什么组合看**：单看 PE 会被盈利周期骗——盈利暴跌时 PE 会突然变得很高，看着"贵"，其实股价已经跌很多了。配合走势和市赚率一起看，能区分「真的贵」和「盈利暂时塌了」。

**怎么读**：理想底部形态是**股价跌 + PE 不高 + 市赚率 < 1** 三者同时出现。如果股价跌但 PE 很高，说明是盈利在下滑，不是估值便宜。

**注意**：三张图都是**月频**，且 ROE 是反推近似值。

## 主线二：情绪与资金（判断"热不热"）

### M3 · 韭圈儿神奇指标

**是什么**：指标原话是——「**沪深300 指数基金的累计涨幅，跌至与偏债混合基金相若时，往往就是市场见底时**」。

**算法**：把两条曲线都归一化到 `2004-12-31 = 1000`：
- 红线：沪深300 全收益（官方 H00300）
- 橙线：**偏债混合基金指数**——历史段用万得 885003.WI 的真实缓存（该段不可变），
  缓存末日之后由申万宏源混合偏债基金指数(807330) 按末值等比续接（云端每日刷新）

**怎么读**：**看两条线的距离**。

| 形态 | 含义 |
|---|---|
| 两线**相距很远**（红线在上） | 股票基金大幅跑赢债基，市场偏热 |
| 两线**交汇**（红线跌到橙线附近） | 股票基金几年白干，等于买债基 → 历史级底部信号 |
| 红线**跌破**橙线 | 极端低估，历史上极少见 |

**直觉**：如果一个高风险资产（股票基金）在好几年里的收益，跟一个低风险资产（偏债基金）一样，那承担风险的意愿就被彻底磨没了——这通常就是情绪冰点。

**注意**：885003.WI 是 Wind 专有指数、没有免费接口，所以**历史段是缓存**（不会变，也因此不会失真）；但它的**末日之后每天由 807330 续接**，所以这张图的日期和其他图一样会每天前进。

### M4 · 偏股基金 3 年滚动年化

**是什么**：公募偏股基金指数过去 **3 年**的年化收益率，每天滚动计算。

**算法**：`3年滚动年化 = (当前点位 ÷ 3年前点位)^(1/3) − 1`

**页面上看到的**：当前读数（如 4.99%）、历史曲线、以及中证全指的叠加走势。

**怎么读**：

| 读数 | 含义 | 通常对应 |
|---|---|---|
| > +30% | 三年翻倍以上 | 牛市中后段，随时可能均值回归 |
| 10%–20% | 温和正收益 | 正常年份 |
| **0 附近或为负** | 三年白干 / 亏损 | **历史级底部区域** |

**为什么有效**：公募基金的三年滚动收益有很强的**均值回归**特性。三年年化 −10% 的时候，往后三年的期望收益往往很高；三年年化 +40% 的时候，往后往往很难看。这是「用后视镜做前瞻」的少数几个还算靠谱的用法。

**注意**：这是**滞后指标**，它告诉你现在的位置，不预测什么时候转向。底部可能持续很久。

### M5 · 顶部共振

**是什么**：把**偏股基金指数**和**一级债基**的累计收益放在一起比，从 `2007-12-31 = 1000` 起算。核心洞察是——**一级债基的累计收益线，就是偏股基金的「估算顶线」**。

|---|---|
| 2015-06 | 1.04 |
| 2021-02 | 1.08 |

**怎么读**：**看形态，不看分位**。当偏股线逼近甚至上穿债基线（比值接近或超过 1）时，就是顶部共振信号。

**注意**：起点选在 2007 年末的顶部，本质上是「事后诸葛」——用已知的顶来标定。原作者和本页都保留了这个原始设定，但你要知道它对「过拟合」的质疑是敞开的。**只把它当辅助参考，别当精确刻度。**

### M6a / M6b / M6c · 三棱镜三连

**是什么**：「三棱镜」是一套**风格轮动**的分析范式：把两头的指数做成一条比值曲线，再从**三个视角**同时看它——所以叫"三棱镜"。

三张图的对比对象不同：

| 图 | 分子 ÷ 分母 | 比的是什么 |
|---|---|---|
| **M6a** | 300成长创新（全收益） ÷ 300价值稳健（全收益） | 大盘内部的**成长 vs 价值** |
| **M6b** | 1000成长创新（全收益） ÷ 1000价值稳健（全收益） | 中小盘内部的**成长 vs 价值** |
| **M6c** | 沪深300 ÷ 中证1000 | **大盘 vs 小盘**（市值维度，不是风格） |

> **M6c 要特别区分**：它比的是市值，不是风格。所以它的"前一边"是**大盘**、"后一边"是**小盘**，读法与 M6a/M6b 的"成长/价值"不同。

#### 三个信号分别在测什么

这是整套指标最容易搞混的地方。三个信号**性质不同，只有 ② 管方向**：

| 编号 | 信号 | 测什么 | 性质 | 管方向吗 |
|---|---|---|---|---|
| **①** | 比值突破/跌破 **252 日布林带**上下轨 | **位置**极端（离常态有多远） | 位置 | ❌ 不指示 |
| **②** | 比值在 **五年均线**上方还是下方 | **中期水位** | 位置 | ✅ **唯一方向来源** |
| **③** | **40 日收益差的滚动分位**（≥90% 过热 / ≤10% 过冷） | **短期涨速** | **反转**（与 M9 同口径） | ❌ 不指示 |

**一句话记住**：**①②③ 只回答"现在有多异常"，方向只看 ②。**

为什么会这样分？因为**位置会延续、涨速会回归**——这两件事的统计性质相反，不能混在一起读：

- **位置**（比值 vs 五年均线）：一旦跌破，短期趋势往往延续（见下方实算）。
- **涨速**（40 日收益差）：涨速在数学上无法长期维持，到极端必然回归（M9 用的就是这个性质）。

> **历史遗留说明**：本页早期版本把 ③ 写成「40 日收益差均线穿越 0 轴」并当作**动量趋势**信号，方向与 M9 正好相反，属口径混用。现已统一为**反转**口径（涨速分位极值），并明确它不参与方向判断。

#### 三个时间尺度

三个信号对应三个不同的时间窗，混用就会自相矛盾：

| 尺度 | 看什么 | 回答的问题 | 实算依据（四指标） |
|---|---|---|---|
| **1–2 个季度** | ② 比值 vs 五年均线 | 该配哪一边 | 跌破均线后 120 交易日，比值**继续下跌占 65%–100%** |
| **1–2 个月** | ③ 40 日涨速分位 | 现在能不能动手 | 极冷后 20–40 日 **78%–96% 回升**；过热后 **68%–93% 继续回落** |
| **约一年** | 独立事件统计（备注最后一行） | 之后会不会反转 | 跌破下轨后一年反弹仅 **20%–50%**，多数继续走弱 |

#### 实算数据（2026-11 初，按"每次事件"独立计段）

| 指标 | 跌破均线后 120 日继续跌 | 跌破布林下轨后一年反弹 | 刚进入均线某侧后一年反弹 |
|---|---|---|---|
| M6a 300成长/价值 | 100%（6 次） | 27%（15 次） | 样本仅 4 次，不给 |
| M6b 1000成长/价值 | 65%（17 次） | 33%（24 次） | 25% / 31%（各 16 次） |
| M6c 沪深300/1000 | 75%（12 次） | 20%（15 次） | 38% / 42%（13 / 12 次） |
| M7 国证成长/价值 | 90%（12 次） | 50%（26 次） | **0%** / 11%（各 9 次） |

**结论：这套信号是「趋势确认」，不是「反转预警」。** 触发之后大概率延续，而不是掉头。

#### 信号汇总里那四行备注怎么读

备注列是四层结构，从上到下依次是「结论 → 依据 → 一年统计 → 信号明细」：

```text
→ 短期偏向买 300价值                                  ← ① 结论（方向 + 强度）
比值 0.886（300成长÷300价值）低于五年均线 22%：
是300成长跑输，不是它便宜；但300成长40日涨速极冷
（分位<1%），1–2 个月内易反弹                          ← ② 依据（含时机提示）
↺ 历史 15 次跌破下轨，一年后 27% 反弹 —— 多数继续走弱    ← ③ 一年尺度
信号 3/3：比值跌破布林下轨、40日涨速过冷（分位<1%）      ← ④ 明细（带标的定语）
```

逐层对照：

| 层 | 读法 | 关键点 |
|---|---|---|
| **① 结论行** | 「短期偏向买 X」 | X 是对比两边的**后一边或前一边**；「短期」特指 **1–2 个季度**。措辞分三档：`n≥2 且偏离≥5%` → 偏向买；`n≥1` → 略偏；否则 → 暂偏 |
| **② 依据行** | 比值多少、高于/低于均线几个点 | 必读那句「**是 X 跑输，不是它便宜**」——比值是相对强弱，不是价格高低 |
| **② 后半句** | 「但 X 涨速极冷/过热」 | 这是**时机**提示，**不改变方向**：极冷说明前一边短期跑输过头，1–2 个月内大概率收窄；过热说明别追高 |
| **③ 一年行** | 历史 N 次、反弹 X% | 按"每次事件"独立统计。**不是**拿"处于某状态的所有日子"算的（那种算法会得出"跌久了就会涨"的假象） |
| **④ 明细行** | 哪几个信号触发了 | 每个信号**都带标的定语**（如「300成长40日涨速过冷」），避免"是谁过冷"的歧义 |

#### 四个常见误读

1. **比值 ≠ 价格。** 两条指数是**同基点**的（2005-01-01 分别约 985.77 / 982.17），现在前者 11,380.81、后者 12,847.47。比值 0.886 记的是**累计涨幅差 154 个百分点**，不是"成长在打折"。判断"便宜"要看 PE/PB（见 M12），不是看点位。
2. **跌破下轨 ≠ 见底。** 布林带会随之**下移**，下轨不是画在纸上的固定支撑。「极端」和「底部」是两件事。
3. **「易反弹」≠「会涨」。** 它指**差值修复**，两条路都算：前一边涨得比后一边快，**或者后一边跌得比前一边多**。后者同样会让差值收窄。
4. **信号数 ≠ 方向。** 3/3 全触发也可能是"偏价值"，因为 ①③ 只表异常度。读数标签现在写「**异常信号偏多（不指示方向）**」，而不是早期的"轮动信号触发"。

#### 统计口径上的坑（重要）

判断"跌破之后会不会反弹"时，**不能用「处于该状态的所有日子」来统计**：

- ❌ 错误做法：把比值在均线下方的每一天都算一个样本 → 连续下跌段被重复计数几百次，样本堆在趋势末端 → 得出"跌久了就会涨"（曾得出 +8% 的假象）
- ✅ 正确做法：**每次进入该状态只算一次**（`跌破布林下轨 15–29 次`、`进入均线某一侧 9–18 次`），样本独立

改成独立计段后结论完全反转：**跌破下轨后一年反弹率只有 20%–50%，多数继续走弱。**

#### 页面上看到的四个读数

| 读数 | 含义 | 注意 |
|---|---|---|
| **ratio（比值）** | 当前分子÷分母 | 上升＝前一边占优 |
| **布林上/下轨**（252 日 ±2σ） | 比值的常态波动范围 | 突破＝位置极端，不代表方向 |
| **五年均线**（1250 日） | 比值的中期水位 | **方向只看它**：在上方＝前一边占优，下方＝后一边 |
| **40 日收益差 / 其 252 日均线** | 最近 40 天的相对涨速 | 看**滚动分位**判过热/过冷，是**反转**性质 |

> 早期版本这里把 `ma5` 误写成"5 日均线"，实际是**五年均线（1250 交易日）**，特此更正。

### M7 · 三棱镜（国证成长 vs 国证价值）

**是什么**：同一套「三棱镜」范式，标的换成**国证成长(399370) ÷ 国证价值(399371)**，覆盖全市场而不限于沪深300 成分股。

**和 M6a/M6b 的关系**：读法**完全一致**（三个信号、三个时间尺度、四层备注都一样），区别只在标的与历史长度：

| | M6a | M6b | **M7** |
|---|---|---|---|
| 样本空间 | 沪深300 成分 | 中证1000 成分 | **全市场**（国证风格指数） |
| 历史起点 | 2008-01 | 2008-01 | **2005-01**（更长） |
| 代表含义 | 大盘内部风格 | 小盘内部风格 | **A 股整体的风格钟摆** |

**为什么三个都要看**：M6a 只看大盘、M6b 只看小盘，都可能被局部行情带偏；M7 覆盖全市场，更能代表"钱在整个 A 股里往成长还是往价值走"。三者方向一致时信号更硬，背离时说明风格切换只发生在某一市值层。

**这个比值在统计上最"干脆"**：

- 进入五年均线下侧共 **9 次**，一年后 **0 次反弹**（全部继续走弱），中位 −11.8%
- 跌破五年均线后 120 日，**90% 继续下跌**
- 跌破布林下轨 26 次，一年后反弹 50%（四个指标里唯一接近各半的）

也就是说：**M7 的"跌破均线"最不该当作抄底信号**，它历史上没有一次在一年内反转回去。

**当前读数（2026-11 初）**：比值 0.596，低于五年均线 0.7347 约 **−19%**，已跌破布林下轨；40 日涨速分位 <1%（极冷）。按上面的框架读：

- **方向（1–2 季度）**：偏**国证价值**（比值在均线下方）
- **时机（1–2 个月）**：国证成长涨速极冷 → 短期跑输过头，这个差距 1–2 个月内大概率收窄，**别在这个位置继续追跌成长**
- **一年**：历史 26 次跌破下轨，一年后仅 50% 反弹 —— 涨跌接近各半，不给强结论

**注意**：原文用国证成长100(980080) / 价值100(980081)，但这两个标的没有公开历史行情接口，改用同一编制机构（深证信息）的 399370 / 399371，风格含义一致但成分不完全相同。

### M13 · 交易集中度

**是什么**：全市场**成交额排名前 N 的股票占总成交额的比例**。衡量资金是不是在往少数几只票里挤。

**页面上看到的**：当前集中度（如 42.69%）、历史分位（如 85.4%）、警戒线 45%、周度/月度版本、以及中证全指 K 线的叠加。

**怎么读**：

| 读数 | 含义 |
|---|---|
| 集中度**高**（分位 > 80%，接近或超过 45% 警戒线） | 资金抱团少数龙头，**抱团越紧，瓦解时越惨** |
| 集中度**低**（分位 < 20%） | 资金分散，普涨普跌行情 |

**关键用法——必须和 M14 合看**：

> **集中度高（抱团紧）＋ 担保比例低（杠杆满）＝ 抱团瓦解叠加去杠杆，是最危险的组合。**

单独看集中度高不是坏事（可能是产业趋势），但一旦杠杆也绷紧了，那就是 2015 年 6 月和 2021 年 2 月的结构。

**注意**：历史集中度用「新浪成交量 × 收盘价」估算，最新值用腾讯实时实测，两者口径略有差异。

### M14 · 融资盘担保比例（227% 强平线）

**是什么**：全市场两融账户的**平均担保比例** =（现金 + 证券市值）÷ 融资负债。

**为什么盯 227%**：这是监管和券商实务中常被引用的**强平警戒线**。担保比例接近这条线时，券商会要求补保证金；跌破就强制平仓——而强制平仓本身会加剧下跌，形成踩踏。

**页面上看到的**：当前比例（如 257.60%）、距 227% 的距离（+30.60 个百分点）、历史分位（21.9%）、历史最低/最高、以及历史上破线多少天/多少轮。

**怎么读**：

| 读数 | 含义 |
|---|---|
| 距 227% **很远**（比如 +50pt 以上） | 杠杆安全，没有被动去杠杆压力 |
| 距 227% **很近**（+10pt 以内） | 危险区，一点下跌就可能触发连锁强平 |
| 历史分位 **低**（如 21.9%） | 当前杠杆水平在历史上偏低，反而说明出清较充分 |

**注意**：
1. 分位低是**好事**（杠杆已经降下来了），但分位低只意味着「下行空间小」，不代表马上涨。
2. 2010 年以前的部分数据是估算段（约 68 天），不是实测。
3. 这个指标有**明显滞后**（数据日通常比行情晚几天），看的时候注意它自己的日期。

## 主线三：红利专题（判断"防守资产位置"）

### M8 · 红利股息率

**是什么**：中证红利指数的**股息率**，以及它相对国债的**风险溢价**。

**页面上看到的几个数**：
- `dy`：中证红利股息率（如 4.49%）
- `cn10y`：10 年期国债收益率（如 1.65%）
- `spread`：风险溢价 = dy − cn10y（如 2.84%）
- `dy_long`：上证红利长周期估算股息率（如 4.58%）

**怎么读**：

- **股息率绝对值越高 → 红利越便宜**。4.5% 的股息率意味着光靠分红 22 年回本（不算股价变动）。
- **风险溢价 spread 越大 → 红利相对债券越有吸引力**。spread 2.84% 表示红利比国债多给近 3 个点的现金回报。
- 看历史分位判断极端程度，而不是看绝对值。

**注意——这张图的长期曲线是估算的**：中证红利的日频股息率官方只提供最近约 20 个交易日（靠每日运行累积）。长周期曲线是用上证红利反推的：
```
派息率 = 当前股息率 × 当前市盈率（中证官方锚定）
历史股息率 = 派息率 ÷ 历史滚动市盈率
```
**这是估算，看长期分位可以，绝对数值请以日频真实值为准。**

### M9 · 红利 40 日收益差

**是什么**：红利指数与宽基指数最近 40 个交易日的涨跌幅之差。

**页面上看到的**：`d40`（当前差值，如 +14.30）和 `d40ma`（差值的均线，如 −0.52）。

**怎么读**：

| 形态 | 含义 |
|---|---|
| d40 大幅为**正**（如 +14） | 红利短期明显跑赢，**防守风格占优**，通常出现在市场下跌或避险情绪中；但**短期已透支** |
| d40 大幅为**负** | 红利短期大幅跑输，**进攻风格占优**，市场在追成长；往往对应红利的**相对买点** |

**关键：这是「涨速」指标，性质是反转，不是趋势。** 实算（按每次进入超买/超卖区独立计段）：

| 状态 | 之后 20 日 | 之后 40 日 |
|---|---|---|
| d40 **> +8**（27 次） | 中位 **−9.4pt**，85% 回落 | 中位 **−9.1pt**，**96% 回落** |
| d40 **< −4**（62 次） | 中位 **+5.2pt**，90% 回升 | 中位 +3.8pt，80% 回升 |

所以正确用法是**看极值、做反向**：冲到 +8 以上别追，回落到零轴甚至以下才是相对买点。

> **口径统一说明**：早期版本曾把「d40 上穿 d40ma 且转正」当作"风格切向红利的可靠信号"——那是**趋势读法**，与本指标的均值回归性质正好相反，已删除。M6a/b/c/M7 的第 ③ 个信号也同步从"穿零轴"改成了**分位极值**口径，四处统一。

**为什么用红利做防守标尺**：红利股（高股息、低估值、波动小）是 A 股最典型的防御资产。当资金从成长往红利搬，说明风险偏好在下降。

**注意**：这里的"回落"指**相对涨幅收窄**，不是红利绝对价格下跌。d40 从 +15 回到 +5，只说明红利不再大幅跑赢，不等于红利要跌。

### M10 / M10b · 红利回归曲线

**是什么**：中证红利指数相对其**长期趋势通道**的位置，用 Z 值衡量。M10 和 M10b 的区别只在用哪个指数：

| 图 | 用哪个指数 | 特点 |
|---|---|---|
| **M10** | 中证红利 **价格指数** 000922 | 对标传统 K 线点位，但漏掉分红 |
| **M10b** | 中证红利 **全收益** H00922 | 含分红再投，**更贴合原文，不低估约 2%/年** |

**怎么读**：**看 Z 值（相对位置），不看绝对点位**。

- Z > +2：显著高于趋势通道上沿，短期偏贵
- Z 在 −2 ~ +2：通道内正常运行
- Z < −2：跌破通道下沿，历史级便宜

**为什么强调"别看绝对点位"**：全收益指数长期单调向上（因为分红一直在再投入），点位本身没有意义，只有「相对趋势线的偏离」才有信息量。

**建议**：**以 M10b 为准**，M10 保留是为了对照传统看盘习惯。

### M11 · 红利 AH 40 日收益差

**是什么**：同一批公司（红利股里同时在 A 股和 H 股上市的），A 股与 H 股最近 40 个交易日的相对表现。

**怎么读**：
- d40 为正 → A 股跑赢 H 股，**境内资金更积极**
- d40 为负 → H 股跑赢，**外资/港股资金更积极**

**为什么有用**：A/H 两地上市的是同一家公司、同样的基本面，价格差异纯粹反映**两地资金的情绪和流动性差异**。所以这个差值是一个很干净的「资金偏好」指标，不受公司质地干扰。

**注意**：涉及汇率折算，极端值（如 ±10 以上）才有解读价值。

# 第八部分 · 自动更新

**每天 18:30（北京时间）自动更新一次。**

```yaml
# .github/workflows/update.yml
schedule:
  - cron: '30 10 * * *'   # 10:30 UTC = 18:30 北京时间
```

工作流做的事：装依赖 → 判断缓存充不充足（`cache/csi*.csv` ≥ 15 个走 `--quick` 增量模式）→ 跑 `fetch_data.py` → 跑 `build.py` 打包 → 生成 `llms.txt` 等 AI 摘要 → **数据新鲜度告警** → 提交 `index.html anchor_v2.html data.json version.txt llms.txt snapshot.md latest.json cache/`。内容没有变化时自动跳过提交。

> **2026-11-13 新增一道可见性兜底**：提交前跑 `check_freshness.py`，若 `data.json` 里仍有卡片落后全站最新日 ≥2 天、或 ≥8 张卡片同时滞后，就打 `::warning::`（**绝不 fail 整轮**，节假日 / 披露滞后属正常）。中证官网 WAF 曾让 12 张卡片连续多日「沿用旧缓存」而 workflow 仍 `success`、日志只有一行不起眼的跳过提示，告警让这类停更立刻可见。主取数本身已能经 `/api/csindex` 自愈，详见附录 L。

> `data.js` 不在提交列表里：它是 `data.json` 的副本（`window.DATA=` + JSON），纯冗余。`build.py` 发现缺失会自动现生成。

## 想改更新时间？

改上面那行 cron 即可。换算规则：**北京时间 − 8 小时 = UTC**。

| 想要的时间 | cron 写法 |
|---|---|
| 每天 18:30（当前） | `30 10 * * *` |
| 每天 20:00 | `0 12 * * *` |
| 仅周一至周五 18:30 | `30 10 * * 1-5` |
| 每天两次（18:30 + 次日 08:00） | `30 10 * * *` + `0 0 * * *` |

> cron 用 UTC，且受 GitHub 调度拥挤影响可能延后几分钟，属正常现象。

## 为什么原作者停用了云端定时任务，这里却能开？

> 与上游的完整差异清单见顶部「[和上游原版（wwww1998）比，改了些什么](#和上游原版wwww1998比改了些什么)」，这里只说定时任务这一件事。

原作者在 2026-09-18 主动注释掉了 schedule，注释里写明原因——**本机与云端双写互相覆盖**：

1. 云端 checkout 仓库里的 `template.html` 重建 `index.html`，覆盖了本机用新版模板推出的完整版 → 页面出现「数据补充中」空白卡；
2. 云端不提交 `version.txt`，前端版本探针读到旧版本号 → 误判「已是最新」，问题被锁死。

本仓库是**云端单写**：没有任何本机计划任务往这里推，`template.html` 与 `index.html` 永远由同一次构建产出，因此不存在上述冲突；并且本工作流的提交已包含 `version.txt`，版本探针能正常推进。

# 第十一部分 · 维护须知

1. **`cache/` 目录不要删。** 里面有 2005 年以来的指数历史，中证官网有 WAF 限流，重抓一次要很久。
2. **改页面只改 `template.html`，改完一定要跑 `build.py`。** 直接改 `index.html` 会被下次构建覆盖。
3. **改动后如果页面出现「数据补充中」空白卡**，通常是 `template.html` 与 `index.html` 不同步，跑一次 `python build.py` 即可。
4. **提交内容里必须包含 `version.txt`**，否则前端版本探针会卡在旧版本。
5. **Wind 缓存只当历史用。** 885003/885006 的本地缓存是**不可变历史段**（数据永不再变），M3/M3b/M5 的续接点之后由云端源（807330 / H11023）每日续接，所以这几张图的日期现在也会每天前进。**不要删 `cache/wind885003.csv`、`cache/wind885006.csv`**，删了会退化到 25/75 合成口径，历史曲线会被改写。
6. **新增指标时，`make_llm_summary.py` 的 `META` 和 `reading()` 要同步改。** `META` 决定该指标在摘要里叫什么、归到哪一组、判读口径怎么写；`reading()` 决定它的读数怎么压成一行。漏改不会报错，但摘要里那一行会显示「（读取失败：…）」并把原始 JSON 附上。
7. **换数据源 = 三处一起改，缺一不可。** `fetch_data.py` 只管数据，**页面上显示的文字是写死的**：
   `template.html` 里的卡片标题、图表图例、`<details>` 说明都有硬编码的标的名称（如「万得全A」「885003.WI」），
   另有 `make_llm_summary.py` 的 `META`（进 `latest.json`/`llms.txt`/邮件）和 `README.md`。
   只改 `fetch_data.py` 不会报错，但页面会出现「新数据配旧口径」——这是本项目最容易漏的一类错误。
   改完务必 `python build.py` 重建 `index.html`，否则前端仍是旧文案。
   **换源若改变了指标的水平值（不只是走势形态），判定阈值必须重新设定**——M1 换到中证全指后
   偏离度整体挪位，阈值就不能沿用旧口径那一套。漏做这一步同样不报错，但「高位/低位」的灯会一直
   错着亮，比文案写错更危险。阈值散在四处，改的时候要一起动：`template.html`（`rM1()` / `rM1b()`
   的 KPI 与结论句 + `buildSummary()`）、`build.py`（`rebuild_anchor()` 里 anchor_v2 的三档区间）、
   `make_llm_summary.py`（`META` 判读口径 + 给大模型的说明段）、`README.md`。
8. **摘要文件是构建产物，不要手改。** 改了下次构建会被覆盖；要调整内容请改 `make_llm_summary.py`，本地先跑 `python make_llm_summary.py --check` 预览，满意再正式生成。

### ⚠️ 密钥为什么不能写在代码里

这个仓库是**公开**的，`gas-earl-daily.gs` 也在其中。Google 和 FRED 都有自动化扫描器，
一旦把密钥写进代码并被公开抓取，密钥会被**直接作废**（Gemini 报 `403 Your API key was reported as leaked`；
FRED 同样会被封）。所以密钥一律走 `setGeminiKey` / `setFredKey` 存进「项目设置 → 脚本属性」，代码里永远是空的。
代码本身不需要任何修改就能跑（只是没有 AI / 美债时会自动降级）。

### 密钥出问题怎么排查

先跑一次 `keyDiag()`，它会把结论直接打出来。常见几种情况：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `keyDiag` 显示属性 0 个 | 这个项目从没成功跑过 `dailyMain`（连 `LAST_ASOF` 都没有） | 多半是换过项目：**脚本属性是项目级的**，新项目一片空白，密钥得重设；定时器也只挂在具体项目上 |
| 跑了 `setGeminiKey` 但属性还是空 | 直接在函数下拉里选中 `setGeminiKey` 运行了 —— 它带参数，直接跑等于没传 | 改成把密钥填进 `setupKeys()` 再运行 `setupKeys` |
| 提示「❌ 没有保存：这是文档里的占位符」 | 把 `粘贴密钥` / `替代防泄密` 这类占位文字当密钥传进去了 | 换成真密钥；`keyReject_()` 会把非 ASCII、超短、占位符挡在写库之前 |
| Gemini 报 403 `reported as leaked` | 密钥被 Google 判定泄露并**永久作废**，改配置没用 | 去 AI Studio 新建一把，再 `setupKeys` 重设 |
| FRED 报 HTTP 400 `not registered` | 密钥无效/写错 | 核对是否为 32 位小写字母+数字 |
| FRED 报 HTTP 500 | **FRED 服务端抖动**，与密钥无关 | 脚本已自动退避重试 3 次（1.5s / 3.5s）；仍失败就等下一次，或临时把 `WITH_FRED` 设为 `false` |

- 跑 `listGeminiModels()`：它会直接问 Google 你这把密钥能用哪些模型，列不出来时分两种情况给出对应修法（密钥作废 / 没开 Generative Language API）。
- 模型改名或下线：脚本会自动发现你账号下能用的对话模型并优先使用，一般不用手改 `GEMINI_MODELS`。
- **两个项目都装了触发器**会收到两封邮件，去「触发器」里删掉多余的那个。

### 会主动不发的情况

- **数据日没推进**：当看板数据日（邮件按 `latest` 字段判定）与上次成功发送相同，默认跳过（`SKIP_IF_UNCHANGED=true`），避免重复发同一天数据；连续 3 次没推进会改发一封「数据卡住」提醒。
- **周末 / 节假日**：默认 `WEEKDAYS_ONLY=false`（每天跑），但因为上面这条去重，数据不更新的日子不会发重复邮件。若要严格只工作日发，把 `CONFIG.WEEKDAYS_ONLY` 改成 `true`。

### K.2 两处根因（都不报错）

**根因 1 · M4 叠加线被拉成一条直线**

`cache/zzqz985.csv`（中证全指 000985 收盘）停在 `20261019,5292.21`。`fetch_data.py` 的 `fetch_zzqz985()` 走中证 `csindex_api` 分块接口，云端 GitHub Actions 的 IP 天天撞 WAF 403 → 触发全局熔断 → 「沿用旧缓存」。随后 M4 里 `zz.reindex(s.index).ffill()` 把这个旧值一路向前填充，尾部连续 **14 个交易日全是 5292.21**，图上表现为「不涨不跌」的假横盘；原版同期是 `5306.57, 5283.5, 5154.03, …, 5146.73`。

**根因 2 · M6a 比值方向反转**

`SERIES["H31586"] = [("csi","931586",True), ("csi","931586CNY01",True)]`：`931586` 是**价格指数**（≈7200），`931586CNY01` 是**全收益指数**（≈13100），两者标了 `same=True` 允许 `merge()` 合并以拉长历史。当 CNY01 被 WAF 熔断、缓存末日**落后于** 931586 时，`merge(keep="last")` 会把价格指数的尾部接到全收益曲线后面：

```text

原版(正确)  m6a.cur = {ratio: 0.8768, a: 11546.06, b: 13168.11, date: 2026-11-06}
```

`13179.82 → 7236.71` 是 **-44.8%** 的单日断崖，`ratio` 从 0.88 翻成 1.63、40 日收益差方向反转，但 `prism()` 照样输出、`workflow` 照样 success。

**为什么原版正常**：上游 `wwww1998/earl-etf-dashboard` 最新提交 `ea0c472` 只改 `data.json` / `index.html` / `version.txt`，**缓存文件并未同步到公开仓库**；原版作者在本机跑取数，本机 IP 没被中证官网 WAF 限流。用户仓在 GitHub Actions 云 IP 跑，所以同样一套代码，用户版会静默用旧缓存和错误合并值生成页面。

### K.4 关键实证：为什么「直接同源续接」而不是「比例换算」

原方案写的是「回退腾讯源做比例续接」，实测后发现**不需要、也不应该**做比例换算：

| 对拍 | 结果 |
| --- | --- |
| `zzqz985.csv.close` vs `tc_000985_ohlc.csv.close` | **5289 个重叠交易日逐值一致**，均差 `0.00`，仅 47 日有 `0.01` 的两位小数舍入差（历史遗留，非本次引入） |
| 原版页面 M4 叠加列 vs `tc.close` | `2026-10-20 ~ 11-04` 共 **12 个交易日逐值一致** |
| 补入的 14 行 vs `tc.close` | 严格 0 差 |
| 补入的 14 行 vs 修复后 `zzqz985.csv` | 完全一致 |

两者本就是**同一份中证全指 000985 官方收盘**，只是两条独立缓存链路（一个 `date=YYYYMMDD` 单列 close，一个 `date=YYYY-MM-DD` 带 OHLC）。同源直连比比例换算更准、更简单、可复现，且不依赖任何外部页面。

> **踩过的坑（别再犯）**：中证 `index-perf` 会把周末/节假日填成与相邻交易日**完全相同**的一行（例 `2026-10-25` 与 `2026-10-26` 四列一致）。补数时**不能**用「与上一行 OHLC 相同」判非交易日——那会误删紧随其后的真实交易日 10-26。必须按**交易日历**过滤：`_zz_trade_calendar()` 取多份中证系缓存日期的并集（各缓存刷新有先后，930950 常落后一两天）。

### L.1 一句话结论

**P0-P1 不能自愈，本次做的是能自愈的根治 + 两层兜底。**

| 方案 | 做什么 | 下次 403 会怎样 | 能自愈吗 |
| --- | --- | --- | --- |
| 只做 P0 | 把 `stale` 变成 workflow `::warning::` | 数据照样停更，只是**看得见** | ❌ |
| 只做 P1 | 修护栏 1 的自指交易日历 | 只有 M4 一条叠加线不拉直线，其余 18 个指标照样停更 | ❌ |
| P0 + P1 | 上面两者相加 | 19 个指标数据日仍冻结，多一条告警 | ❌ |
| **本次（根治 + P0 + P1）** | 直连 403 → 自动走 Worker 取同一官方数据 | **数据日照常前进**，与原版对齐 | ✅ |

原因很直接：P0 是「告警」、P1 是「局部症状修复」，**两者都没碰「云 IP 403 → 全局熔断 → 沿用旧缓存」这条根链路**。
403 在 11-03~11-13 连续 10 次运行里天天出现，几乎必然再来，所以只做 P0-P1 下次照样差好几天。

### L.2 根因（诊断证据链）

- **连续 10 次运行（11-03~11-13）天天触发全局熔断**，每次 5~11 次 403，无一例外。
- 17 份 `csi*.csv` + `sw807330.csv` + `zzqz985.csv` 全部冻结在 `20261111`；腾讯 / 国证 / 乐咕 / 利率等旁路都到 `20261112` —— **只有中证官网这一条链路断了**。
- 本仓 `11-13 02:30` 更新、全站到 11-12；原版 `11-13 21:19` 更新、多数到 11-13。**19 个指标无一领先，全部落后 1~2 天**，`data.json` 的 `stale` 自己就列了 12 张滞后卡片。
- `workflow` 的守卫只查「文件存在 + JSON 合法」，**不查数据日期**，所以停更 10 天照样 `success`。
- **原版为什么没事**：原作者停用云端定时任务改本机跑（本机 IP 不撞中证 WAF），且原版代码有 `--no-csi` 把中证尾部取数从主流程剥离；其仓库里 `cache/*.csv` 其实停在 10 月，本机缓存不入库。原版熔断阈值甚至更敏感（`2`），根本用不上。

### L.3 三个让停更「无法自愈」的设计缺陷（本次全部处理前三个里的关键项）

1. **备用源形同虚设**：`fetch_all()` 里 `same=False` 的腾讯备用，只要主源返回 ≥250 行旧缓存就完全跳过。带 `same=True` 的 `000300/000922/000852/000015` 能合并到 11-12，而 `930903/931589/931586` 和 11 个无备用系列只能停在 11-11。**这条不能简单改成 `True`** —— 会重演附录 K 修过的全收益 / 价格指数串线。本次**不碰 `same` 标记**，改从传输通道解决。
2. **护栏 1 自指失效**（= P1）：11-08 加的 `tc_000985_ohlc` 同源续接，其交易日历取自 5 份**同样被冻结**的 `csi*.csv`，导致 11-12 那行被过滤。日志里「腾讯兜底补齐至 11-12」有，但「护栏1 续接 zzqz985」一次都没出现。本次修日历并集。
3. **`stale` 只写文件、不告警**（= P0）：workflow 不检查数据日期。本次加 `check_freshness.py`。

> 另发现一个**不影响根因的时间异常**：cron 写 `30 10 * * *`（北京 18:30），但 10 次 schedule 实际落在北京 `00:33~04:52`，偏移约 8 小时。这让本仓「次日凌晨抓数」天然拿不到当日收盘、比原版「当天傍晚抓数」晚一天，叠加熔断把体感差距放大。**本次不改 cron**（GitHub 调度延迟属平台行为，改 cron 收益不确定且属于「改调度」），根治后数据按最新交易日前进，体感差距消失。

### L.9 给 AI 的维护边界（复制这段）

1. **不要把 `/api/csindex` 当成「换了数据源」**：它转发的是中证官网同一个 `index-perf`，字段/单位/口径/阈值都没变。任何「换源要四处一起改 + 重设阈值」的动作在这里**不适用**；真换源时照旧按第 11 部分第 7 条办。
2. **不要删 `CSI_VIA_WORKER` / `_csindex_via_worker`**，也不要把 Worker 回退挪到熔断之后 —— 一旦熔断打开，整轮 `fetch_csi` 会直接跳过，自愈就失效了。
3. **不要改 Worker 仓库的 `/api/csindex` 响应结构**（`date`/`close` 字段名与含义），见 `a-stock-api` README §0「响应结构是契约」。本仓 `_csindex_via_worker()` 依赖 `date` 可归一化成 `YYYYMMDD`、`close` 为数值。
4. **Worker 也失败时不要强行重试或改 `same` 标记**：原有熔断 / 冷却 / 沿用旧缓存是第三层兜底，P0 告警会让它可见。批量改 `same=True` 会重演附录 K 的全收益 / 价格指数串线。
5. **不要改 `check_freshness.py` 让它 `exit 1`**：节假日 / 披露节奏差异属正常，局部容错是设计（附录 C）。摘要的「数据滞后提示」段由 `make_llm_summary.py` 生成，别在这里重复写。
6. **不要修 cron 时间异常**（L.3 已说明）：它不影响数据口径自愈，改调度收益不确定，且属于「改 cron」需同步第八部分。
7. **护栏 1 的交易日历必须包含 `tc_000985_ohlc.csv`**：它是唯一在中证源整条冻结时仍刷新的同源序列，删掉会退回 11-08 之后那个「护栏静默失效」的状态。
8. **线上写操作照旧**：精确 `git add`（白名单）、中文 commit、`git pull --rebase`、**绝不 `--force`**；完整产物由 `update.yml` 提交。

**回滚**：`git revert <本修复 commit>` 即可。`fetch_data.py` 是纯增量函数 + 两处分支、`check_freshness.py` 是新增独立脚本、`update.yml` 只加一步，回滚不影响任何 `cache/`、口径或产物；但回滚后「中证 403 → 连续停更」会原样复发，P0 告警也会消失。
