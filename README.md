### 为什么需要「给 AI 的摘要」这几个文件

主页面是一个 3.4MB 的自包含 HTML，**AI 抓取器读不到里面的数字**，实测：

| 项目 | 实测 |
|---|---|
| `index.html` 总字符 | 3,437,505 |
| 其中 3 个 `<script>` | 3,351,767（占 97.8%） |
| 剥掉脚本后的纯文本 | 仅 13,258 字符 |
| 静态 HTML 里能否搜到当前读数 | **不能**（`257.6`、`42.69`、`4.49` 全部搜不到） |

三个原因：

1. **数值全在 JS 变量里**——所有读数存在 `window.DATA` 这个 2.2MB 的对象中，不执行 JavaScript 的抓取器只能看到 `m14:{ratio:257.6,...}` 这样的裸代码；
2. **图是 canvas 画的**——ECharts 把曲线画进位图，DOM 里没有任何 `<text>`，就算执行了 JS 也抓不到文字；
3. **体积超限**——3.4MB 超过多数 AI 网页抓取工具 1MB 左右的正文阈值。

所以每日构建会额外产出三份纯文本：

| 文件 | 大小 | 内容 |
|---|---|---|
| `llms.txt` | 8.6KB | 20 个指标的当前读数 + 各自数据截止日 + 判读口径 + 交叉判读提示 + 名词速查 |
| `snapshot.md` | 8.6KB | 同上内容的 Markdown 版（在 GitHub 上可直接渲染阅读） |
| `latest.json` | 7.6KB | 同上内容的结构化版本，字段与 `data.json` 的 `cur` 一致 |

**用法**：把 `llms.txt` 的地址发给大模型（或直接把全文贴进对话框），它就能真的回答「现在 A 股什么位置」，而不只是复述指标定义。

# 第一部分 · 先搞懂五个基础概念

这一节比后面的指标列表更重要。看不懂指标，通常是这几个概念没通。

## 1. 分位（百分位）—— 看板里最重要的读数

**分位 = 当前值在历史样本里的排名位置。**

- 「85.4% 分位」的意思是：**历史上只有 14.6% 的时间，这个指标比现在更高。**
- 「20% 分位」的意思是：历史上 80% 的时间都比现在高，现在处在很低的位置。

分位的好处是把不同量纲的指标拉到同一把尺子上。绝对数值往往没有可比性（比如市盈率 12 倍是高还是低，得看历史上它一般在什么区间），而分位直接告诉你「在历史里算贵还是便宜」。

> ⚠️ **分位的陷阱**：它依赖样本区间。样本只有 3 年和样本有 20 年，同一个数值的分位可能差很多。所以本页每张图都标注了自己的历史起点，看的时候留意一下。

## 2. 价格指数 vs 全收益指数 —— 差别是一年约 2%

- **价格指数**：只跟踪股价涨跌，**把分红扔掉了**。上证指数、沪深300 都是价格指数。
- **全收益指数**：把分红也再投进去，所以长期走势比价格指数高，**大约每年高 2%**（A 股股息率水平）。

所以同一个「沪深300」，价格指数和全收益指数拉长十年看，能差出一大截。做长期比较时**必须用全收益指数**，否则会系统性低估。

看板里 `H00300`（沪深300全收益）、`H00922`（中证红利全收益）就是官方全收益指数。凡是标注「价格指数」的图，都会说明「收益与偏离度系统性偏低约 2%/年」。

## 3. 归一化（rebase 到 1000）—— 为什么两条线能放一起比

把两条曲线都从某个起点重新标定为 1000，之后按涨幅同比缩放。这样两条不同点位（比如 4000 点和 1200 点）的指数就能放在同一张图上比较「谁涨得多」。

看板里常见的起点：`2004-12-31 = 1000`、`2007-12-31 = 1000`。**起点选在哪里会显著影响结论**，这点在看 M5 时要特别注意。

## 4. 40 日收益差 —— 衡量「风格轮动」

是指标 A 减去指标 B 在最近 40 个交易日的涨跌幅之差，单位是百分点。

- 正值越大 → A 明显跑赢 B，风格偏向 A
- 负值越大 → B 明显跑赢 A

40 个交易日约等于两个月，这个窗口既能过滤掉日内噪音，又足够灵敏地捕捉风格切换。看板里画的是「差值」和「差值的均线」两条线，**均线穿越零轴**往往才是可靠的切换信号，单日跳一下不算。

## 5. 「三项指标一起看」原则

单个指标几乎一定会骗人。估值低的时候往往还能更低，情绪热的时候往往还能更热。看板的正确用法是：

> **估值 + 情绪 + 资金，三条线同向时才下结论。**

比如：「估值分位只 20%（便宜）」+「偏股基金 3 年滚动年化 −5%（情绪冰点）」+「两融担保比例贴近 227%（杠杆已出清）」——三个方向都指向底部，这个结论就比单看一个 PE 靠谱得多。

# 第二部分 · 名词速查

| 名词 | 含义 |
|---|---|
| **PE (TTM)** | 市盈率 = 股价 ÷ 最近 12 个月每股盈利。越低越便宜 |
| **PB** | 市净率 = 股价 ÷ 每股净资产 |
| **ROE** | 净资产收益率 = 净利润 ÷ 净资产，衡量赚钱效率 |
| **盈利收益率** | = 1 ÷ PE。市盈率的倒数，可以直接和债券利率比大小 |
| **股息率** | 每股分红 ÷ 股价。红利策略的核心指标 |
| **风险溢价** | 股息率 − 10 年期国债收益率。股票相对债券多给的补偿 |
| **市赚率 (PR)** | = PE ÷ (ROE×100)。本质是「用多少倍 PE 买到 1% 的 ROE」，PR < 1 通常视为低估 |
| **滚动年化** | 把过去 N 年的累计收益换算成每年的复合收益率 |
| **布林带** | 均线上下各加 2 个标准差形成的通道。突破上轨＝过热，跌破下轨＝超跌 |
| **Z 值** | 当前值偏离均值多少个标准差。+2 以上偏高，−2 以下偏低 |
| **两融担保比例** | 融资融券账户的（现金+证券市值）÷ 负债。低于 227% 会触发强制平仓 |
| **基期归一** | 把曲线从某天重新定为 1000，之后按涨幅缩放，方便两条不同点位的线对比 |
| **滞后期 / 数据截止** | 每个数据源的发布节奏不同，图上标的是该指标自己最后一根数据的日期 |

# 第四部分 · 逐个指标详解

## 主线一：估值与性价比（判断"贵不贵"）

### M1 · 五年之锚（中证全指 000985 偏离率）

**是什么**：用**中证全指(000985)**（万得全A 的等价代理，同为全市场宽基综合指数、走势高度一致）相对它自己**五年移动平均线**偏离了多少。这是张翼轸最出名的指标之一，用来判断 A 股整体处在周期的什么位置。

**算法**：`偏离率 = (当前点位 ÷ 五年均线 − 1) × 100%`，再算这个偏离率在历史上的分位。

**页面上看到的**：五年均线、当前偏离率（%）、偏离率的历史分位、以及一条 10 年分位曲线。

**怎么读**：

| 读数 | 含义 | 通常对应 |
|---|---|---|
| 偏离率 > +10% | 高于五年均线 | 偏高，暂停定投、考虑分批减仓 |
| 偏离率 −5% ~ +10%，分位 40–60% | 均值附近 | 震荡市，无明确方向 |
| 偏离率 < −5% | 低于五年均线 | 低位区间，可加大买入 |
| 偏离率 < −20% | 显著低于五年均线 | 极端底部区域 |

**阈值（重要）**：`+10% / −5%` 是**给中证全指这一条序列单独定的**，不是通用刻度。换指数会让偏离度的**水平值整体挪位**（中证全指比万得全A 低约 5pt 量级），所以任何其他口径的门槛都不能直接搬过来；反过来，也别用本页的读数去套别人的历史文章。**本页内部（M1 / M1b / `anchor_v2.html`）用的是同一套中证全指偏离度**，口径一致。

**注意**：用的是**价格指数**（中证全指全收益版没有公开源），所以偏离度会比全收益口径系统性偏低约 2%/年。看趋势和相对高低不受影响，但别拿绝对值跟别人的全收益口径比。

---

### M1b · 五年之锚（原文口径）

**是什么**：M1 的原始版本。原文的核心判断是「**跌破五年均线下浮 20%，就是可以抄底的位置**」。

**怎么读**：页面会统计历史上这个条件被触发的次数（图上显示为「⬆x 次 / ⬇y 次」）。看的是**触发频率**，不是当前值本身——如果历史上平均两三年才触发一次，而现在正在触发，那就是很强的信号。图上的穿越箭头阈值与中证全指口径配套：**⬆ 红箭头＝偏离 ≤ −20%**（正好是跌破 MA×0.8 的位置），**⬇ 绿箭头＝偏离 ≥ +25%**，同方向 60 个交易日只标一次。

**和 M1 的区别**：M1 是「连续的分位曲线」，M1b 是「离散的触发计数」。M1 告诉你「现在多便宜」，M1b 告诉你「历史上这种便宜到什么程度出现过几次」。

### M2 · 股债性价比

**是什么**：把**股票的盈利回报**和**债券的利息回报**放在一起比。也叫 FED 模型 / 格雷厄姆指数。

**算法**：
```
盈利收益率 = 1 ÷ 沪深300市盈率
股债性价比 = 盈利收益率 − 10年期国债收益率
```
直觉理解：沪深300 现在的盈利回报率如果是 7%，而国债只有 1.65%，那买股票的「基础回报」比买国债高出 5.35 个百分点——这个差值越大，股票越划算。

**页面上看到的**：市盈率、市赚率（PR）、股债性价比曲线。

**怎么读**：

- **差值越高 → 股票相对债券越便宜 → 该多配股票**
- **差值越低（甚至为负）→ 股票相对债券太贵 → 该多配债券**
- 看历史分位：> 80% 分位说明股票性价比处于历史高位

**注意**：
1. 这个指标是**月频**（因为免费的指数 PE 只有月频），不是每天都能看到新点。
2. 市赚率 `PR = PE ÷ (ROE×100)`，本页的 ROE 是 `PB ÷ PE` 反推的近似值，不是财报直接披露的。PR < 1 一般视为低估。

---

### M12 · 沪深300 估值一图看全

**是什么**：把沪深300 的**走势、市盈率、市赚率**三张图上下排列，一次看全估值三要素。

**为什么组合看**：单看 PE 会被盈利周期骗——盈利暴跌时 PE 会突然变得很高，看着"贵"，其实股价已经跌很多了。配合走势和市赚率一起看，能区分「真的贵」和「盈利暂时塌了」。

**怎么读**：理想底部形态是**股价跌 + PE 不高 + 市赚率 < 1** 三者同时出现。如果股价跌但 PE 很高，说明是盈利在下滑，不是估值便宜。

**注意**：三张图都是**月频**，且 ROE 是反推近似值。

## 主线二：情绪与资金（判断"热不热"）

### M3 · 韭圈儿神奇指标

**是什么**：指标原话是——「**沪深300 指数基金的累计涨幅，跌至与偏债混合基金相若时，往往就是市场见底时**」。

**算法**：把两条曲线都归一化到 `2004-12-31 = 1000`：
- 红线：沪深300 全收益（官方 H00300）
- 橙线：**偏债混合基金指数**——历史段用万得 885003.WI 的真实缓存（该段不可变），
  缓存末日之后由申万宏源混合偏债基金指数(807330) 按末值等比续接（云端每日刷新）

**怎么读**：**看两条线的距离**。

| 形态 | 含义 |
|---|---|
| 两线**相距很远**（红线在上） | 股票基金大幅跑赢债基，市场偏热 |
| 两线**交汇**（红线跌到橙线附近） | 股票基金几年白干，等于买债基 → 历史级底部信号 |
| 红线**跌破**橙线 | 极端低估，历史上极少见 |

**直觉**：如果一个高风险资产（股票基金）在好几年里的收益，跟一个低风险资产（偏债基金）一样，那承担风险的意愿就被彻底磨没了——这通常就是情绪冰点。

**注意**：885003.WI 是 Wind 专有指数、没有免费接口，所以**历史段是缓存**（不会变，也因此不会失真）；但它的**末日之后每天由 807330 续接**，所以这张图的日期和其他图一样会每天前进。

### M3b · 韭圈儿·基金净值口径

**是什么**：M3 的「原著口径」版本——不合成指数，直接用**一只真实基金的净值**当债券腿，更有体感。

**怎么读**：判读逻辑与 M3 完全一致，仍是看两条累计涨幅曲线的交汇。区别只是债券腿换成真实基金净值曲线，波动比指数更毛糙，但更贴近「一个普通投资者实际拿到的体验」。

### M4 · 偏股基金 3 年滚动年化

**是什么**：公募偏股基金指数过去 **3 年**的年化收益率，每天滚动计算。

**算法**：`3年滚动年化 = (当前点位 ÷ 3年前点位)^(1/3) − 1`

**页面上看到的**：当前读数（如 4.99%）、历史曲线、以及中证全指的叠加走势。

**怎么读**：

| 读数 | 含义 | 通常对应 |
|---|---|---|
| > +30% | 三年翻倍以上 | 牛市中后段，随时可能均值回归 |
| 10%–20% | 温和正收益 | 正常年份 |
| **0 附近或为负** | 三年白干 / 亏损 | **历史级底部区域** |

**为什么有效**：公募基金的三年滚动收益有很强的**均值回归**特性。三年年化 −10% 的时候，往后三年的期望收益往往很高；三年年化 +40% 的时候，往后往往很难看。这是「用后视镜做前瞻」的少数几个还算靠谱的用法。

**注意**：这是**滞后指标**，它告诉你现在的位置，不预测什么时候转向。底部可能持续很久。

---

### M5 · 顶部共振

**是什么**：把**偏股基金指数**和**一级债基**的累计收益放在一起比，从 `2007-12-31 = 1000` 起算。核心洞察是——**一级债基的累计收益线，就是偏股基金的「估算顶线」**。

**为什么用一级债基做顶线**：一级债基主要做债券 + 打新（后来改投可转债），是一个「稳赚不亏但赚不多」的基准。历史上两次大顶，偏股基金都恰好涨到「只比一级债基略高」的位置：

| 顶部 | 偏股 ÷ 债基 比值 |
|---|---|
| 2015-06 | 1.04 |
| 2021-02 | 1.08 |

**怎么读**：**看形态，不看分位**。当偏股线逼近甚至上穿债基线（比值接近或超过 1）时，就是顶部共振信号。

**注意**：起点选在 2007 年末的顶部，本质上是「事后诸葛」——用已知的顶来标定。原作者和本页都保留了这个原始设定，但你要知道它对「过拟合」的质疑是敞开的。**只把它当辅助参考，别当精确刻度。**

### M5b · 顶部共振 · 易方达增强回报

**是什么**：M5 的同源思路，但债券腿换成 @qzy69 原始使用的真实基金——**易方达增强回报（110017）**。

**和 M5 的区别**：该基金 2008-03-19 才成立，所以两条曲线改从「两者首个共同交易日」归一化到 1000，起点更晚。一级债基含打新增强，真实累计收益高于普通纯债，是**最贴近原文的本土口径**。

**怎么读**：同样看偏股线是否逼近紫线（债基收益线）。纵轴用对数坐标，比值 = 偏股 ÷ 一级债基。

### M6a / M6b / M6c · 三棱镜三连

**是什么**：「三棱镜」是一套**风格轮动**的分析范式：把两头的指数做成比值曲线，再从三个视角同时看。

三张图的对比对象不同：

| 图 | 分子 ÷ 分母 |
|---|---|
| **M6a** | 300成长创新（全收益） ÷ 300价值稳健（全收益） |
| **M6b** | 1000成长创新（全收益） ÷ 1000价值稳健（全收益） |
| **M6c** | 沪深300 ÷ 中证1000（大盘 vs 小盘） |

**页面上看到的四个读数**（重要性从高到低）：

1. **d40（40 日收益差）**：最近 40 个交易日两者涨跌幅之差，单位百分点。**最灵敏的轮动信号。**
2. **ratio（比值）**：当前成长÷价值的值。数值上升＝成长占优。
3. **布林带**（boll_mid / up / dn）：比值的均线和上下轨。**跌破下轨＝成长被极端压制**，历史上常有反弹。
4. **ma5**：比值的 5 日均线，短期方向。

**怎么读**：**d40 穿越零轴**是最实用的信号——从负转正说明成长开始跑赢，从正转负说明价值开始跑赢。配合布林带位置确认：d40 刚转正 + 比值还在下轨附近 = 成长可能要反攻。

**注意**：M6a/M6b 用的是**全收益**版成长价值指数，M6c 是纯大小盘对比（沪深300 vs 中证1000），本质不是风格而是市值维度。

### M7 · 三棱镜（国证成长 vs 国证价值）

**是什么**：同一套「三棱镜」范式，标的换成**国证成长(399370) ÷ 国证价值(399371)**，覆盖全市场而不限于沪深300 成分股。

**怎么读**：与 M6 完全一致，看 ratio、布林带、d40。区别是这个比值的历史更长（2005 年起），更能代表 A 股整体的风格钟摆。

**注意**：原文用国证成长100(980080) / 价值100(980081)，但这两个标的没有公开历史行情接口，改用同一编制机构（深证信息）的 399370 / 399371，风格含义一致但成分不完全相同。

### M13 · 交易集中度

**是什么**：全市场**成交额排名前 N 的股票占总成交额的比例**。衡量资金是不是在往少数几只票里挤。

**页面上看到的**：当前集中度（如 42.69%）、历史分位（如 85.4%）、警戒线 45%、周度/月度版本、以及中证全指 K 线的叠加。

**怎么读**：

| 读数 | 含义 |
|---|---|
| 集中度**高**（分位 > 80%，接近或超过 45% 警戒线） | 资金抱团少数龙头，**抱团越紧，瓦解时越惨** |
| 集中度**低**（分位 < 20%） | 资金分散，普涨普跌行情 |

**关键用法——必须和 M14 合看**：

> **集中度高（抱团紧）＋ 担保比例低（杠杆满）＝ 抱团瓦解叠加去杠杆，是最危险的组合。**

单独看集中度高不是坏事（可能是产业趋势），但一旦杠杆也绷紧了，那就是 2015 年 6 月和 2021 年 2 月的结构。

**注意**：历史集中度用「新浪成交量 × 收盘价」估算，最新值用腾讯实时实测，两者口径略有差异。

### M14 · 融资盘担保比例（227% 强平线）

**是什么**：全市场两融账户的**平均担保比例** =（现金 + 证券市值）÷ 融资负债。

**为什么盯 227%**：这是监管和券商实务中常被引用的**强平警戒线**。担保比例接近这条线时，券商会要求补保证金；跌破就强制平仓——而强制平仓本身会加剧下跌，形成踩踏。

**页面上看到的**：当前比例（如 257.60%）、距 227% 的距离（+30.60 个百分点）、历史分位（21.9%）、历史最低/最高、以及历史上破线多少天/多少轮。

**怎么读**：

| 读数 | 含义 |
|---|---|
| 距 227% **很远**（比如 +50pt 以上） | 杠杆安全，没有被动去杠杆压力 |
| 距 227% **很近**（+10pt 以内） | 危险区，一点下跌就可能触发连锁强平 |
| 历史分位 **低**（如 21.9%） | 当前杠杆水平在历史上偏低，反而说明出清较充分 |

**注意**：
1. 分位低是**好事**（杠杆已经降下来了），但分位低只意味着「下行空间小」，不代表马上涨。
2. 2010 年以前的部分数据是估算段（约 68 天），不是实测。
3. 这个指标有**明显滞后**（数据日通常比行情晚几天），看的时候注意它自己的日期。

## 主线三：红利专题（判断"防守资产位置"）

### M8 · 红利股息率

**是什么**：中证红利指数的**股息率**，以及它相对国债的**风险溢价**。

**页面上看到的几个数**：
- `dy`：中证红利股息率（如 4.49%）
- `cn10y`：10 年期国债收益率（如 1.65%）
- `spread`：风险溢价 = dy − cn10y（如 2.84%）
- `dy_long`：上证红利长周期估算股息率（如 4.58%）

**怎么读**：

- **股息率绝对值越高 → 红利越便宜**。4.5% 的股息率意味着光靠分红 22 年回本（不算股价变动）。
- **风险溢价 spread 越大 → 红利相对债券越有吸引力**。spread 2.84% 表示红利比国债多给近 3 个点的现金回报。
- 看历史分位判断极端程度，而不是看绝对值。

**注意——这张图的长期曲线是估算的**：中证红利的日频股息率官方只提供最近约 20 个交易日（靠每日运行累积）。长周期曲线是用上证红利反推的：
```
派息率 = 当前股息率 × 当前市盈率（中证官方锚定）
历史股息率 = 派息率 ÷ 历史滚动市盈率
```
**这是估算，看长期分位可以，绝对数值请以日频真实值为准。**

### M9 · 红利 40 日收益差

**是什么**：红利指数与宽基指数最近 40 个交易日的涨跌幅之差。

**页面上看到的**：`d40`（当前差值，如 +14.30）和 `d40ma`（差值的均线，如 −0.52）。

**怎么读**：

| 形态 | 含义 |
|---|---|
| d40 大幅为正（如 +14） | 红利明显跑赢，**防守风格占优**，通常出现在市场下跌或避险情绪中 |
| d40 大幅为负 | 红利大幅跑输，**进攻风格占优**，市场在追成长 |
| **d40 上穿 d40ma 且转正** | 风格切向红利的可靠信号 |

**为什么用红利做防守标尺**：红利股（高股息、低估值、波动小）是 A 股最典型的防御资产。当资金从成长往红利搬，说明风险偏好在下降。

**注意**：+14 这种极端值往往意味着**短期已充分反映**，不一定是继续加仓红利的好时点，反而要警惕均值回归。

### M10 / M10b · 红利回归曲线

**是什么**：中证红利指数相对其**长期趋势通道**的位置，用 Z 值衡量。M10 和 M10b 的区别只在用哪个指数：

| 图 | 用哪个指数 | 特点 |
|---|---|---|
| **M10** | 中证红利 **价格指数** 000922 | 对标传统 K 线点位，但漏掉分红 |
| **M10b** | 中证红利 **全收益** H00922 | 含分红再投，**更贴合原文，不低估约 2%/年** |

**怎么读**：**看 Z 值（相对位置），不看绝对点位**。

- Z > +2：显著高于趋势通道上沿，短期偏贵
- Z 在 −2 ~ +2：通道内正常运行
- Z < −2：跌破通道下沿，历史级便宜

**为什么强调"别看绝对点位"**：全收益指数长期单调向上（因为分红一直在再投入），点位本身没有意义，只有「相对趋势线的偏离」才有信息量。

**建议**：**以 M10b 为准**，M10 保留是为了对照传统看盘习惯。

### M11 · 红利 AH 40 日收益差

**是什么**：同一批公司（红利股里同时在 A 股和 H 股上市的），A 股与 H 股最近 40 个交易日的相对表现。

**怎么读**：
- d40 为正 → A 股跑赢 H 股，**境内资金更积极**
- d40 为负 → H 股跑赢，**外资/港股资金更积极**

**为什么有用**：A/H 两地上市的是同一家公司、同样的基本面，价格差异纯粹反映**两地资金的情绪和流动性差异**。所以这个差值是一个很干净的「资金偏好」指标，不受公司质地干扰。

**注意**：涉及汇率折算，极端值（如 ±10 以上）才有解读价值。

# 第五部分 · 页面怎么读

1. **先看顶部「数据截止」**。每张图的数据源发布节奏不同（有的 T+0、有的 T+5），页面会为滞后的图单独标注「沿用最近可得数据」及其日期。**不要以为所有图都是同一天的。**
2. **看分位，不看绝对值**。所有指标都给历史分位，80% 以上和 20% 以下才是有意义的信号区。
3. **注意「估算」标记**。M8 的长周期曲线、M14 的早期数据、M2/M12 的月频估值，都有口径妥协，当趋势参考别当精确值。
4. **不用手动刷新**。页面加载时先拉几十字节的 `version.txt` 做比对，版本一致直接用缓存，不一致才下载 2MB 的 `data.json`。这是为跨境慢链路做的优化。
5. **带红色标记的图**需要额外谨慎，通常标注意味着该指标存在口径替代或估算。

# 第八部分 · 自动更新

**每天 18:30（北京时间）自动更新一次。**

```yaml
# .github/workflows/update.yml
schedule:
  - cron: '30 10 * * *'   # 10:30 UTC = 18:30 北京时间
```

工作流做的事：装依赖 → 判断缓存充不充足（`cache/csi*.csv` ≥ 15 个走 `--quick` 增量模式）→ 跑 `fetch_data.py` → 跑 `build.py` 打包 → 提交 `index.html data.json data.js version.txt cache/`。内容没有变化时自动跳过提交。

## 想改更新时间？

改上面那行 cron 即可。换算规则：**北京时间 − 8 小时 = UTC**。

| 想要的时间 | cron 写法 |
|---|---|
| 每天 18:30（当前） | `30 10 * * *` |
| 每天 20:00 | `0 12 * * *` |
| 仅周一至周五 18:30 | `30 10 * * 1-5` |
| 每天两次（18:30 + 次日 08:00） | `30 10 * * *` + `0 0 * * *` |

> cron 用 UTC，且受 GitHub 调度拥挤影响可能延后几分钟，属正常现象。

## 为什么原作者停用了云端定时任务，这里却能开？

原作者在 2026-09-18 主动注释掉了 schedule，注释里写明原因——**本机与云端双写互相覆盖**：

1. 云端 checkout 仓库里的 `template.html` 重建 `index.html`，覆盖了本机用新版模板推出的完整版 → 页面出现「数据补充中」空白卡；
2. 云端不提交 `version.txt`，前端版本探针读到旧版本号 → 误判「已是最新」，问题被锁死。

本仓库是**云端单写**：没有任何本机计划任务往这里推，`template.html` 与 `index.html` 永远由同一次构建产出，因此不存在上述冲突；并且本工作流的提交已包含 `version.txt`，版本探针能正常推进。

# 第十一部分 · 维护须知

1. **`cache/` 目录不要删。** 里面有 2005 年以来的指数历史，中证官网有 WAF 限流，重抓一次要很久。
2. **改页面只改 `template.html`，改完一定要跑 `build.py`。** 直接改 `index.html` 会被下次构建覆盖。
3. **改动后如果页面出现「数据补充中」空白卡**，通常是 `template.html` 与 `index.html` 不同步，跑一次 `python build.py` 即可。
4. **提交内容里必须包含 `version.txt`**，否则前端版本探针会卡在旧版本。
5. **Wind 缓存只当历史用。** 885003/885006 的本地缓存是**不可变历史段**（数据永不再变），M3/M3b/M5 的续接点之后由云端源（807330 / H11023）每日续接，所以这几张图的日期现在也会每天前进。**不要删 `cache/wind885003.csv`、`cache/wind885006.csv`**，删了会退化到 25/75 合成口径，历史曲线会被改写。
6. **新增指标时，`make_llm_summary.py` 的 `META` 和 `reading()` 要同步改。** `META` 决定该指标在摘要里叫什么、归到哪一组、判读口径怎么写；`reading()` 决定它的读数怎么压成一行。漏改不会报错，但摘要里那一行会显示「（读取失败：…）」并把原始 JSON 附上。
7. **换数据源 = 三处一起改，缺一不可。** `fetch_data.py` 只管数据，**页面上显示的文字是写死的**：
   `template.html` 里的卡片标题、图表图例、`<details>` 说明都有硬编码的标的名称（如「万得全A」「885003.WI」），
   另有 `make_llm_summary.py` 的 `META`（进 `latest.json`/`llms.txt`/邮件）和 `README.md`。
   只改 `fetch_data.py` 不会报错，但页面会出现「新数据配旧口径」——这是本项目最容易漏的一类错误。
   改完务必 `python build.py` 重建 `index.html`，否则前端仍是旧文案。
   **换源若改变了指标的水平值（不只是走势形态），判定阈值必须重新设定**——M1 换到中证全指后
   偏离度整体挪位，阈值就不能沿用旧口径那一套。漏做这一步同样不报错，但「高位/低位」的灯会一直
   错着亮，比文案写错更危险。阈值散在四处，改的时候要一起动：`template.html`（`rM1()` / `rM1b()`
   的 KPI 与结论句 + `buildSummary()`）、`build.py`（`rebuild_anchor()` 里 anchor_v2 的三档区间）、
   `make_llm_summary.py`（`META` 判读口径 + 给大模型的说明段）、`README.md`。
8. **摘要文件是构建产物，不要手改。** 改了下次构建会被覆盖；要调整内容请改 `make_llm_summary.py`，本地先跑 `python make_llm_summary.py --check` 预览，满意再正式生成。

# 第十二部分 · 每天早上收一封邮件（可选）

`gas-earl-daily.gs` 是配套的邮件脚本，跑在 **Google Apps Script** 上，免费、不用服务器。
它每天定时读取本仓库的 `latest.json` / `llms.txt`，拼成一封带「温度计 + 四张机会卡 + 宏观对照 + 20 个指标明细 + 两条经验规则」的 HTML 邮件发到你邮箱。

### 分工

| 角色 | 在哪跑 | 干什么 |
|---|---|---|
| 数据看板（本仓库） | GitHub Pages + Actions | 每天 18:30 抓数、算指标、生成 `latest.json` / `llms.txt` |
| 邮件脚本（`gas-earl-daily.gs`） | Google Apps Script | 每天 19:15 读取上面两个文件，发邮件 |

> **想让 AI 帮你分析时，喂 `llms.txt`（推荐）。** 它把 20 个指标的当日读数、截止日、判读口径、交叉判读方法和名词解释都压成 ~9KB 的纯文本，直接整段贴给 Gemini / ChatGPT 就行，不需要再补背景。
> `latest.json`（7.6KB）是同一份内容的结构化版，适合程序读、或只想要数字时用；`data.json`（2.2MB）是全量日线原始数据，只有自己画图时才需要。
> 三个文件都由 `make_llm_summary.py` 从 `data.json` 生成，**同源同口径**，不会互相矛盾。

### 部署步骤

> 想省事就直接开 **<https://wj624.github.io/earl-etf-dashboard/复制邮件脚本.html>** —— 页面里点「复制全文」，然后跳到第 3 步。

1. 打开 <https://script.google.com/home> → 打开**你已有的项目**（第一次用就点左上「新项目」，建议命名「A股每日解读」）。
2. 把 `gas-earl-daily.gs` 全文粘进编辑器，覆盖掉原来的内容（新项目里是默认的 `myFunction`），`Ctrl+S` 保存。
3. **第一次运行任何函数都会弹授权**：点「高级」→「前往项目（不安全）」→「允许」。这是 Google 对未验证脚本的通用拦截，不是报错。
4. **设置密钥**（只需一次，都不写进代码）。脚本里已经有一个现成的 `setupKeys()`，把两个空引号换成你的密钥：
   ```js
   function setupKeys() {
     setGeminiKey('AIza...你的Gemini密钥');   // 39 位，AIza 开头
     setFredKey('355d...你的FRED密钥');       // 32 位
   }
   ```
   申请地址：Gemini <https://aistudio.google.com/apikey>、FRED <https://fredaccount.stlouisfed.org/apikeys>。
   改完在顶部下拉里选 **`setupKeys`** 运行 → 看到两条 `✅ 已保存…（39 位）/（32 位）` → 再把两个密钥删回空字符串 `''` → `Ctrl+S`。
   > ⚠️ **不要直接选中 `setGeminiKey` / `setFredKey` 运行**——它们是带参数的函数，直接运行等于没传参，只会打印用法、**什么都不会保存**。这是「跑了但没生效」的头号原因。
5. 运行 `keyDiag()`，核对：探针能写能读、两个密钥都显示 `…（39 位）/（32 位）`。
6. 运行 `testConnections()`，看三条链路（数据源 / FRED / Gemini）是否都 ✅。
7. 运行 `previewNow()`，去邮箱看效果（没收到先翻垃圾邮件箱）。
8. 运行 `installDailyTrigger()`，装上每天 19:15 的定时器（会先清空本项目原有触发器，重复跑安全）。
9. 点左侧闹钟图标「触发器」，确认有一条 `dailyMain` / 时间驱动 / 每天 / 下午 7 点~8 点。

### ⚠️ 密钥为什么不能写在代码里

这个仓库是**公开**的，`gas-earl-daily.gs` 也在其中。Google 和 FRED 都有自动化扫描器，
一旦把密钥写进代码并被公开抓取，密钥会被**直接作废**（Gemini 报 `403 Your API key was reported as leaked`；
FRED 同样会被封）。所以密钥一律走 `setGeminiKey` / `setFredKey` 存进「项目设置 → 脚本属性」，代码里永远是空的。
代码本身不需要任何修改就能跑（只是没有 AI / 美债时会自动降级）。

### 密钥出问题怎么排查

先跑一次 `keyDiag()`，它会把结论直接打出来。常见几种情况：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `keyDiag` 显示属性 0 个 | 这个项目从没成功跑过 `dailyMain`（连 `LAST_ASOF` 都没有） | 多半是换过项目：**脚本属性是项目级的**，新项目一片空白，密钥得重设；定时器也只挂在具体项目上 |
| 跑了 `setGeminiKey` 但属性还是空 | 直接在函数下拉里选中 `setGeminiKey` 运行了 —— 它带参数，直接跑等于没传 | 改成把密钥填进 `setupKeys()` 再运行 `setupKeys` |
| 提示「❌ 没有保存：这是文档里的占位符」 | 把 `粘贴密钥` / `替代防泄密` 这类占位文字当密钥传进去了 | 换成真密钥；`keyReject_()` 会把非 ASCII、超短、占位符挡在写库之前 |
| Gemini 报 403 `reported as leaked` | 密钥被 Google 判定泄露并**永久作废**，改配置没用 | 去 AI Studio 新建一把，再 `setupKeys` 重设 |
| FRED 报 HTTP 400 `not registered` | 密钥无效/写错 | 核对是否为 32 位小写字母+数字 |
| FRED 报 HTTP 500 | **FRED 服务端抖动**，与密钥无关 | 脚本已自动退避重试 3 次（1.5s / 3.5s）；仍失败就等下一次，或临时把 `WITH_FRED` 设为 `false` |

- 跑 `listGeminiModels()`：它会直接问 Google 你这把密钥能用哪些模型，列不出来时分两种情况给出对应修法（密钥作废 / 没开 Generative Language API）。
- 模型改名或下线：脚本会自动发现你账号下能用的对话模型并优先使用，一般不用手改 `GEMINI_MODELS`。
- **两个项目都装了触发器**会收到两封邮件，去「触发器」里删掉多余的那个。

### 会主动不发的情况

- **数据日没推进**：当看板数据日（邮件按 `latest` 字段判定）与上次成功发送相同，默认跳过（`SKIP_IF_UNCHANGED=true`），避免重复发同一天数据；连续 3 次没推进会改发一封「数据卡住」提醒。
- **周末 / 节假日**：默认 `WEEKDAYS_ONLY=false`（每天跑），但因为上面这条去重，数据不更新的日子不会发重复邮件。若要严格只工作日发，把 `CONFIG.WEEKDAYS_ONLY` 改成 `true`。
